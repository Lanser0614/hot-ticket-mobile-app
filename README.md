# Hot Ticket Android

Нативное приложение Kotlin / Jetpack Compose для существующего Hot Ticket Mini App.
Сервер: `https://ticket.crosfit.uz`. Android 11+ (minSdk 30).

## Возможности

- Поиск поездов: станции, дата, свободные места, вагоны и переход к покупке на Uzrailpass.
- Поиск авиабилетов: поиск направления через API, прямые рейсы, багаж, пагинация, карточка, покупка и история цен за 30 дней для Pro.
- Ближайшие отправления: сегодня/завтра по нескольким железнодорожным направлениям и ближайшие авиарейсы.
- Общие с Telegram отслеживания: создание маршрута или конкретного поезда, максимальная цена, тип вагона, изменение условий, отключение/возобновление.
- Профиль: русский/узбекский язык, город вылета, класс перелёта, уведомления, тихие часы, тема, экономия, приглашение друга.
- Актуальные тарифы Lite/Pro, заявка, сообщения поддержки и отправка вложения/чека.
- Явно обозначенный демо-режим с примерами данных, без серверных подписок и уведомлений.

## Вход

1. Приложение запрашивает одноразовый код и секрет устройства (`POST /api/android/login`).
2. Открывается `https://t.me/hot_ticket_buy_bot?startapp=android_<code>`.
3. Пользователь сверяет код и явно подтверждает вход в Telegram Mini App.
4. Mini App подтверждает запрос с подписанным Telegram `initData`.
5. Android обменивает секрет устройства на отдельный Bearer-токен и использует существующий `/api/v1`.

Токен хранится в SharedPreferences в зашифрованном виде с ключом Android Keystore;
секреты исключены из backup/device transfer. Только HTTPS, редиректы запросов API запрещены.
Уведомления продолжают приходить через Telegram; Android push в эту версию не входит.

**Для рабочего входа обязательно обновить сервер и Mini App** из соседнего проекта
`C:\Users\User\air\hot-ticket-telegram-bot`. Уже работающий сервер без этих изменений
не знает маршрутов `/api/android/*`. Публикация изменений на сервер в этой задаче не выполнялась.

Android-сессии сейчас хранятся в памяти одного web-процесса: срок 30 дней,
выход отзывает токен, перезапуск сервера требует повторного входа. Для нескольких
web-процессов нужен общий session store (SQLite/Redis) либо sticky routing.
Код подтверждения действует 5 минут; обмен секрета возможен только один раз.

## Сборка

Откройте этот каталог в Android Studio и запустите `app`.

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
# UI-тесты на отдельном запущенном эмуляторе:
$env:ANDROID_SERIAL = 'emulator-5554'
.\gradlew.bat :app:connectedDebugAndroidTest
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Это debug-сборка для установки и
проверки. Для публикации в Google Play нужны release signing и окончательный applicationId.

Сервер задаётся через `BuildConfig.API_BASE_URL` в `app/build.gradle.kts`.
UI-тест проверяет поиск → создание отслеживания → пересоздание Activity → отключение
и смену языка; отдельный тест проверяет HTTPS-валидацию и шифрование сессии.

## Структура

- `MainActivity.kt`: запуск приложения.
- `ui/HotTicketApp.kt`: нативные экраны и состояние ViewModel.
- `data/HotTicketRepository.kt`: запросы API в Dispatchers.IO, таймауты, ошибки и защищённое хранение сессии.
- `ui/theme`: светлая/тёмная тема с цветами текущего Mini App.

Обновление сообщений Pro выполняется кнопкой. Вложения можно отправить; просмотр
входящих вложений и самостоятельный onboarding Android пока не перенесены.
Вход и существующие профили работают независимо от этого; новые пользователи могут
завершить onboarding в Telegram Mini App.
